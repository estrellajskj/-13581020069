# STM32 多功能环境监测时钟

## GitHub 源码版

本仓库包含完整 Keil 源码、淘晶驰 HMI/TFT、原理图资料、测试和联调说明。天气城市默认为杭州；`pin_conf.h` 中的 Wi-Fi 名称、密码和天气 API Key 已清空，需要自行填写后编译。桌面交付工程的已配置版本保持原样。

为避免编译文件携带密钥，本仓库不提交 STM32 HEX、AXF、OBJ、map 或打包 ZIP。使用 Keil ARM Compiler 5.06 和 STM32F1xx_DFP 2.3.0 打开 `firmware/MDK/Template.uvprojx` 并 Rebuild，或执行 `./build.ps1 -Keil '你的UV4.exe路径'`。输出 HEX 位于项目根目录。请在每次提交前确认没有上传个人网络参数或私钥。

`verification/` 保留桌面交付版本的历史编译、屏幕模拟及接口验证记录；历史 HEX 哈希不代表仓库含有该固件。`source-changes.json` 的当前源码哈希已按本仓库更新。此仓库仍未完成实物整机验收。

本交付是按所提供原理图适配的**可编译固件原型及联调资料**，不是已完成实物验收的成品。MQ-135 已改为 MQ-138 的 ADC 采样路径；没有沿用旧 MQ-135 浓度公式。原始桌面工程未被修改。

报警回差：CO₂ 降至 1250ppm 或以下解除；未触发时恰好 1300ppm 不报警，1301ppm 起触发。已标定甲醛路径降至 65µg/m³ 时解除对应报警（当前未启用标定）。STOP 只清除当前闹钟，不屏蔽仍超限的气体报警。气体离线或数据过期会显示故障，不显示成正常浓度。闹钟和亮度设置目前保存在 RAM 中，重新上电恢复默认；DS3231 的有效时间保留。

MQ-138 按用户指定的 ADC 电压阈值报警：上电预热 180 秒后，连续两次有效采样小于 500mV 时触发屏幕 `MQ RAW ALARM`、PB1 LED 和蜂鸣器，连续两次不低于 800mV 时解除，每 2 秒采样一次。未触发状态下，恰好 500mV 不触发。该设置不是甲醛浓度标定，不能据此判断甲醛浓度超标。`BUZZER_OUTPUT_ENABLED=1` 已按用户要求启用；气体报警或闹钟有效时 PB0 每 300ms 高低切换，无报警时低电平。原图 PB0 直接连接 Q2 基极，仍需补全串联限流电阻，软件启用不表示硬件已修正或实测。详见 `verification/气体传感器排查.md`。

## 参数填写

在 `pin_conf.h` 修改以下参数后重新编译：

```c
#define WIFI_NAME "你的2.4GHz路由器名称"
#define WIFI_PASSWORD "你的WiFi密码"
#define WEATHER_CITY "hangzhou"
#define WEATHER_API_KEY "你的心知天气Key"
```

城市使用天气服务支持的城市拼音/ID，或事先 URL 编码的城市字符串。Wi-Fi 名称和密码中的双引号、反斜杠需要按 C 字符串及 AT 指令规则转义；首轮联调建议使用简单 ASCII 热点名称。GitHub 源码版已清空 Wi-Fi 名称、密码和心知天气私钥，查询城市保留杭州 `hangzhou`。天气每 10 分钟更新，超过 30 分钟失效，天气页城市旁标注来源 `Seniverse`。配置说明见 `verification/天气API申请与配置.md`。

天气适配心知天气 `/v3/weather/now.json`，HTTP/1.0、端口 80；需要账户有相应接口权限。HTTPS-only 服务或 chunked 响应当前会被拒绝，不能仅改域名就当作兼容。JSON 使用 jsmn v1.1.0 解析。ESP8266 要有支持 `AT+CIPSNTPCFG`、`AT+CIPSNTPTIME?` 的 AT 固件；原工程的 AP/TCP 服务对象没有在本产品路径创建。

天气现象按心知天气官方代码表显示为中文，保留温度；未知代码显示“未知”，未取得有效数据或数据过期显示“天气暂不可用”。这是天气实况，不是未来降雨预报。此次须同时下载最新 STM32 HEX 和 `screen/` 中的 TFT，旧 TFT 的中文子集字库不包含全部天气汉字。

2026-11-06 已从电脑通过直连 TCP/HTTP 查询真实杭州天气，返回 HTTP 200；捕获响应也通过固件使用的 HTTP/IPD/JSON 解析流程。结果见 `verification/weather-live-test.json`，响应快照见 `verification/weather-live-response.http`。这项验证未经过实体 ESP8266 或 STM32。

## 三项资料边界

1. **CO₂**：已从立创商城对应型号产品页取得赛亚 SY-CO2-28BMI A2.0 厂家规格书。`CO2_PROTOCOL=1`，USART3 为 9600-8-N-1，每 2 秒发送 `FF 01 86 00 00 00 00 00 79`，校验 9 字节 `FF 86` 应答，按高位乘 256 加低位得到 ppm。厂家示例报文已测试得到 394ppm，非实物测量值。错误帧、超范围值不作为新有效数据，超过 10 秒未收到有效应答则失效；不发送校准命令。原问题是此前协议开关为 0，查询和解码均未启用。详见 `verification/气体传感器排查.md`，原始资料在 `hardware/datasheets/SY-CO2-28BMI-A2.0.pdf`。协议依据已确认，实物供电、接线和通信仍待验证。
2. **MQ-138**：原理图只有模拟接口及分压。MQ-138 对多种 VOC 有响应，未标定电压不能直接换算为甲醛 mg/m³，也不能保证区分甲醛或准确判断 0.07mg/m³。按用户要求改成相对响应百分比：`clamp((1500-ADC毫伏)*100/1500,0,100)`，取整数，1500mV 对应 0%，107mV 对应 92%。显示 `REL 92%`，预热时显示 `WARM 92%`，无效采样显示 `-- %`；运行时把屏幕原电压标签更新为 `MQ-138 relative`。这不是空气中甲醛的体积分数或浓度。参考值由 `MQ138_RESPONSE_REFERENCE_MV` 配置，未经真实标定，`MQ138_CALIBRATED` 仍为 0。三点表只是插值接口，默认数值为占位，不能直接启用。真实定量甲醛监测需使用有选择性、量程和精度资料的甲醛模块。
3. **串口屏**：已按后续提供的 `TJC3224T132_011C__A01` 制作原生工程和 TFT，使用编辑器 `TJC3224T132_011` 配置、320×240 横屏。官方编译及模拟器事件回传验证通过；未连接用户实物，下载、触摸、供电及 MCU 联调仍待验证。

## 联调顺序

1. 先处理硬件说明中的电源、蜂鸣器及 I²C 问题。确认 5V、3.3V 和共地，暂不使用电池模式验证。
2. 核对实际 MCU 为 C8T6；用 USB/稳定 5V 电源供电，SWD 下载固件。保留 PA13/PA14。
3. 按 `screen/USB串口下载说明.md` 下载屏幕程序，恢复 STM32 接线后以 9600-8-N-1 验证显示和控制。
4. 检查温湿度、光敏变化和手动亮度；光敏百分比不是校准照度 lux。
5. 填 Wi-Fi / 天气参数，验证真实联网、校时、断网和重连。未校时的失效 RTC 不会被重置为虚假默认时间。
6. 用最新 STM32 HEX 验证 CO₂ 浓度、断线失效、>1300ppm 报警及 ≤1250ppm 解除；MQ-138 验证相对百分比与电压阈值报警。真实甲醛定量测量仍需资料及校准/器件调整。
7. 设置闹钟到下一分钟，验证触发、停止和第二天再次触发。

主机测试通过不等于外设联调通过；本次没有连接实物，也未执行下载或生产测试。

## 启动故障指示

PB1 状态灯使用短闪编码。上电时单闪一次表示 HSE 启动失败，系统已回退到内部时钟并继续启动。屏幕、Wi-Fi、CO₂ UART 初始化失败分别显示 4、5、6 次闪烁，每种故障在启动时报告一次；对应外设停用，其余采集和报警任务继续运行。连续重复的错误码表示致命故障：2 闪为时钟初始化失败，3 闪为 FreeRTOS 调度器无法启动，7 闪为动态内存耗尽，8 闪为任务栈溢出。传感器报警也会使用 PB1 常亮，因此观察启动闪码要看上电后的前几秒。
