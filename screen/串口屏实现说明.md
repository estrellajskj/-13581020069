# 淘晶驰屏幕工程

用户屏幕标签：`TJC3224T132_011C__A01`。工程使用官方出厂工程对应的 `TJC3224T132_011` 设备配置，320×240 横屏，GB2312。编辑软件为官方 USART HMI 1.68.2.3038。

## 文件

- `environment-monitor-TJC3224T132.HMI`：可在 USART HMI 打开、修改和编译的原生工程。
- `environment-monitor-TJC3224T132.tft`：该型号的屏幕下载文件，不是 STM32 程序。
- `fonts/`：三个原生字库。中文字库为本界面使用的字符子集；新增中文时需要重新生成字库。
- `previews/page-0.png` 至 `page-4.png`：官方模拟器生成的初始页面截图，未接实物。
- `events.json`、`layout.json`：工程事件和布局的可读导出，原生 HMI 为编辑入口。
- `USB串口下载说明.md`：没有 TF 卡时的接线、下载和故障排查。
- 编译及模拟器记录见 `../verification/tjc-build.log` 和 `tjc-simulation.log`。

## 页面

| 编号 | 工程名称 | 内容 |
|---|---|---|
| 0 | home | 温湿度、CO2、MQ-138 相对响应百分比、时间、光照、报警状态 |
| 1 | weather | 固件配置的城市、天气、穿衣建议 |
| 2 | clock | 当前日期时间、闹钟小时/分钟加减、启用开关、应用、停止提醒 |
| 3 | brightness | 当前亮度、光照、自动开关、10%～100% 手动滑块 |
| 4 | settime | 年/月/日/小时/分钟/秒加减、应用和返回 |

页面 4 是页面 2 的本地设时子页，不发送 `PAGE=4`。固件仍保留四个主页面协议，在设时页通过同名 `tDate` 显示当前时间，`tAlarm` 是接收更新的隐藏字符串变量。应用后返回页面 2。

年限制为 2000～2099；月、日及时间按范围循环。应用时按月份及闰年缩减无效日期，例如 2027-02-31 调整为 2027-02-28。闹钟和输入值在翻页间保留，屏幕重启恢复工程默认值。闹钟启用后还需点“应用闹钟”。实际 RTC 时间和是否写入成功以单片机回传的当前日期时间为准。

## 串口协议

9600 波特率、8 数据位、无校验、1 停止位。关闭控件自动发送组件 ID；由事件发送 ASCII 行，末尾为真正的 CR LF 两个字节。

| 屏幕发送 | 固件行为 |
|---|---|
| `PAGE=0` 至 `PAGE=3` | 切换主页面并更新固件的活动页面 |
| `ALARM=23:59,1` | 设置每日闹钟，末位 0/1 表示禁用/启用 |
| `STOP` | 停止当前闹钟，不屏蔽仍超限的气体报警 |
| `DIM=45` | 手动亮度 45%，同时关闭自动调光 |
| `AUTO=0` / `AUTO=1` | 关闭/开启自动调光 |
| `SETTIME=2028-02-29T23:04:05` | 设置单片机管理的 RTC 时间 |

导航按钮会先发送 PAGE 行，再本地切页；固件的 `page N` 回传不触发再次发送 PAGE，避免循环。设时子页不改变固件的活动主页面。转换缓冲 `tWork` 是隐藏字符串变量，不占显示位置。

单片机发给屏幕采用淘晶驰指令，每条后面附三个 `0xFF`，例如 `tTemp.txt="25.0 C"`、`dim=70`。不是把文字 `FF FF FF` 加进字符串。项目启动设置 `baud=9600`、`dim=70`、`bkcmd=0`、`recmod=0`，进入首页。

本版固定标签和天气现象使用中文，天气串口文字为 GB2312 字节；其他动态状态保留 ASCII。天气显示如“晴 / 23 C”“小雨 / 18 C”，未知代码显示“未知”，无有效数据显示“天气暂不可用”。按心知天气官方代码表映射：https://docs.seniverse.com/api/start/code.html 。城市及 Wi-Fi/天气 Key 仍在固件 `pin_conf.h` 配置，屏幕不虚构联网或传感器数据。此次需更新 STM32 HEX 和 TFT；16px 字库已补全天气汉字，旧 TFT 缺少部分字形。`previews/weather-0.png` 至 `weather-4.png` 是模拟器注入的显示测试样例，不是实况。

最新 STM32 固件会在首页运行时将 `l3` 改为 `MQ-138 relative`，将 `tHcho` 改为 `REL n%`（预热中 `WARM n%`，无效采样 `-- %`），因此无需重编译或重下载屏幕 TFT。原生 HMI 和预览仍保留初始占位文字；若一直显示 `CO2 protocol?`、`CAL? -- mV` 等初始文字，不能据此判断传感器输出，应先核对主控固件和屏幕通信。

## 已验证与待验证

原生工程保存成功，官方编译器 0 错误、0 警告，峰值页面 RAM 占用 1932/3584 字节。已在官方模拟器重新打开工程、检查五页显示，并通过串口 `click` 指令触发事件验证导航、闹钟、停止、调光、设时、闰年和数值循环。串口注入事件验证不等于实际触摸、串口下载或整机联调通过。

用户已提供实物屏显示照片，本机未连接硬件；真实触摸响应、供电、STM32 串口通信及传感器/网络数据仍需完整实物验证。CO2 协议现已按 SY-CO2-28BMI 厂家 A2.0 规格书启用，由 STM32 更新 `tCO2` 为 ppm。MQ-138 浓度标定和主板硬件待修正项沿用项目现有说明。
